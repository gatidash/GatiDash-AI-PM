The Escalation Matrix

Who decides what, by when, and what happens when nobody answers.

Reference implementation · built for my own concept systems

The problem

Autonomy is a per-action property. Granting it per agent is how systems get too much of it. The same agent that can diff a regulatory publication all day with nobody watching must not send a merchant an email on its own. So the interesting artefact is the table that says which actions sit at which tier. The agent itself is the easy part.

The part teams skip is the timeout. Everyone writes down who approves. Almost nobody writes down what happens at hour five when that person is on leave. Left unspecified, the pragmatic answer creeps in: let it through, we're blocking the business. That's a fail-open default, and it will be the finding in your next audit.

Every row here ends in park, escalate, cancel or suspend. I enforce that in code at policy load, so a well-meaning edit that adds an auto-approve path crashes on import instead of quietly shipping. Two rows matter more than the rest: what happens when the agent abstains, and what happens when it's unsure about something that matters.

SPECIAL ROWS - these override the action-class tier, they never lower it
=================================================================================
ROW A: AGENT ABSTAINED
  Trigger        outcome == "abstained" from any Meridian call, or the merchant
                 agent returning no_confident_intervention.
  Tier           T2 minimum. An abstention is never auto-closed and never
                 downgraded to T1 on the grounds that "nothing happened".
  Reviewer       Named owner for the domain.
  SLA            4 bh.
  Reviewer sees  The abstention reason, the free-text detail, what_would_resolve,
                 every partial finding with its citations, and the source
                 document at the cited offsets. The reviewer starts from the
                 agent's work, not from zero.
  On breach      Escalates to T3 queue. An unreviewed abstention is an open
                 regulatory question with nobody's name on it.
  Why            The agent stopping is a signal, not an absence of one. Silent
                 abstentions are how a backlog of unanswered obligations forms.

ROW B: LOW CONFIDENCE, HIGH IMPACT
  Trigger        confidence.value < 0.72 (illustrative floor, set from the
                 calibration curve) AND impact_band in {high, critical}.
                 Impact band comes from the control's own criticality rating
                 or the merchant's exposure, never from the model.
  Tier           Forced to T2 minimum, T3 if the action class is already T2.
                 Confidence can raise a tier. It can never lower one.
  Reviewer       Named owner. Second reviewer if the band is critical.
  SLA            4 bh.
  Reviewer sees  The confidence value AND its calibration method and set id, a
                 plain-English note that this was auto-escalated for low
                 confidence, and the two nearest precedent cases with their
                 outcomes.
  On breach      Same ladder as T2: page, backup, then cancel and suspend
                 the action class for that account.
  Why            High confidence never buys a tier reduction. The asymmetry is
                 the point: the model can add caution, never remove it.

=================================================================================
INVARIANTS - checked in code at policy load, not left to reviewers
=================================================================================
  I1  No rule may resolve to auto_execute for any action class that moves money,
      contacts a customer, or writes to a control record.
  I2  on_timeout may never be "approve" or "proceed". The only legal values are
      park, escalate, cancel, suspend.
  I3  An unknown or unmapped action class routes to T3, not T0. Default deny.
  I4  Every executed action carries the approver identity, the approval
      timestamp, and the exact payload approved. No approver, no execution.
  I5  Approval is bound to a payload hash. If the agent re-derives the action,
      the old approval is void.
  I6  A tier may be raised at runtime. It may never be lowered at runtime.

hitl/router.py - resolves a tier and refuses to fail open Python 
"""hitl/router.py

Executes the routing policy. Deterministic, no model in the loop.

The router's only job is to answer: what tier, who approves, by when, and what
happens if nobody answers. It answers that last question with something other
than "go ahead", every time.
"""
from __future__ import annotations

import json
from dataclasses import dataclass
from pathlib import Path
from typing import Any

POLICY: dict[str, Any] = json.loads(Path("policy/hitl_routing.v3.json").read_text(encoding="utf-8"))

TIER_ORDER = ["T0", "T1", "T2", "T3"]
LEGAL_TIMEOUT_ACTIONS = {"park", "escalate", "cancel", "suspend", None}
GATED_CLASSES_PREFIXES = ("merchant.send", "merchant.apply", "merchant.change",
                          "merchant.pause", "meridian.attach", "meridian.decommission",
                          "meridian.prepare")


class PolicyError(RuntimeError):
    """Raised at load time. A policy that violates an invariant does not run."""


def _rank(tier: str) -> int:
    return TIER_ORDER.index(tier)


def _max_tier(a: str, b: str) -> str:
    return a if _rank(a) >= _rank(b) else b


def validate_policy(policy: dict) -> None:
    """I2, I1 and I3 are enforced here, at load, not by reviewers at 2am."""
    for tier_id, tier in policy["tiers"].items():
        if tier.get("on_timeout") not in LEGAL_TIMEOUT_ACTIONS:
            raise PolicyError(f"{tier_id}: on_timeout={tier.get('on_timeout')!r} would fail open")
        for step in tier.get("timeout_ladder", []):
            if step["action"] in {"approve", "auto_approve", "proceed", "execute"}:
                raise PolicyError(f"{tier_id}: timeout ladder step {step['action']!r} would fail open")
    for name, spec in policy["action_classes"].items():
        if name.startswith(GATED_CLASSES_PREFIXES):
            tier = policy["tiers"][spec["tier"]]
            if tier["autonomy"] == "execute":
                raise PolicyError(f"{name}: resolves to autonomous execution but touches money, "
                                  f"a customer, or a control record")
    if policy["default_tier"] != "T3":
        raise PolicyError("default_tier must fail closed to T3")


@dataclass(frozen=True)
class Routing:
    tier: str
    autonomy: str
    approvals_required: int
    approver_role: str | None
    sla_minutes: int | None
    on_timeout: str | None
    timeout_ladder: list[dict]
    reviewer_view: list[str]
    applied_overrides: list[str]
    reason: str

    @property
    def may_execute_now(self) -> bool:
        return self.autonomy == "execute"


def route(request: dict, policy: dict = POLICY) -> Routing:
    """request keys:
        action_class, agent_outcome, confidence, impact_band,
        monetary_value_cents, entity_flags, nearest_precedent_similarity
    """
    spec = policy["action_classes"].get(request["action_class"])
    if spec is None:
        base_tier, reason = policy["default_tier"], "unmapped action_class - default deny"
    else:
        base_tier = spec["tier"]
        reason = f"base tier for {request['action_class']}"
        cap = spec.get("value_cap_cents")
        if cap is not None and request.get("monetary_value_cents", 0) > cap:
            base_tier = _max_tier(base_tier, spec["above_cap_tier"])
            reason = f"value {request['monetary_value_cents']} exceeds cap {cap}"

    tier = base_tier
    applied: list[str] = []
    view: list[str] = []

    for ov in policy["overrides"]:
        if not _override_matches(ov["when"], request):
            continue
        candidate = ov["min_tier"]
        bump = ov.get("bump_if_already", {}).get(tier)
        if bump:
            candidate = _max_tier(candidate, bump)
        new_tier = _max_tier(tier, candidate)      # I6: raise only, never lower
        if new_tier != tier:
            reason = f"{reason}; raised to {new_tier} by override '{ov['id']}'"
        tier = new_tier
        applied.append(ov["id"])
        view.extend(ov.get("reviewer_view", []))

    t = policy["tiers"][tier]
    override_timeout = next((ov.get("on_timeout") for ov in policy["overrides"]
                             if ov["id"] in applied and ov.get("on_timeout")), None)

    return Routing(
        tier=tier,
        autonomy=t["autonomy"],
        approvals_required=t["approvals_required"],
        approver_role=t.get("approver_role"),
        sla_minutes=t.get("sla_minutes"),
        on_timeout=override_timeout or t.get("on_timeout"),
        timeout_ladder=t.get("timeout_ladder", []),
        reviewer_view=list(dict.fromkeys(view)),
        applied_overrides=applied,
        reason=reason,
    )


def _override_matches(when: dict, req: dict) -> bool:
    if "agent_outcome" in when and req.get("agent_outcome") not in when["agent_outcome"]:
        return False
    if "confidence_below" in when:
        conf = req.get("confidence")
        if conf is None or conf >= when["confidence_below"]:
            return False
    if "impact_band" in when and req.get("impact_band") not in when["impact_band"]:
        return False
    if "entity_flags_any" in when:
        if not set(req.get("entity_flags") or []) & set(when["entity_flags_any"]):
            return False
    if "nearest_precedent_similarity_below" in when:
        sim = req.get("nearest_precedent_similarity")
        if sim is None or sim >= when["nearest_precedent_similarity_below"]:
            return False
    return True


def on_sla_expiry(routing: Routing, elapsed_minutes: int, emit: Any) -> str:
    """Runs on the queue's timer. Returns the action taken.

    There is no code path here that approves anything. That is the whole design.
    """
    last: dict | None = None
    for step in sorted(routing.timeout_ladder, key=lambda s: s["at_minutes"]):
        if elapsed_minutes >= step["at_minutes"]:
            last = step
    if last is None:
        return "within_sla"
    assert last["action"] not in {"approve", "proceed"}, "fail-open path reached"
    emit("hitl.sla_breach", tier=routing.tier, elapsed_minutes=elapsed_minutes,
         action=last["action"], overrides=routing.applied_overrides)
    return last["action"]


validate_policy(POLICY)   # import-time. A bad policy never reaches production.

The tradeoff

  • Fail-closed timeouts mean real work stalls when an approver is away, and the honest fix is staffing the backup rota rather than softening the rule.
  • Four tiers is a compromise: fewer and everything piles into one queue, more and nobody remembers which is which without opening the document.
  • Routing abstentions to T2 by default guarantees some reviewer time is spent on cases where the agent was simply being over-careful.
  • Letting confidence raise a tier but never lower one throws away most of the efficiency a good calibration curve could buy, and I'll take that until the calibration has years of evidence behind it.
